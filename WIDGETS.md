# When2Gram HTML widget experiment (Bot API 10.4)

This integration adds a compact **private-chat availability editor** without replacing
the existing inline invitations, event management, database, or keyboard fallback.

## Enable in a local checkout

This PR includes the integrated source files; no patch script is necessary.
Install dependencies and run checks from the repository root:

```bash
uv sync --locked --all-groups
uv run ruff check .
uv run pytest -p no:warnings -o addopts=''
```

Set `ENABLE_WIDGETS=true` in `.env` (default: **off**). Start the existing bot
as before. Opening a When2Gram event invitation now sends an HTML widget
in the bot's private chat. The widget also offers a **Classic grid** button for the old keyboard flow.
The event's original inline invitation still links
participants into the private chat, because Telegram currently disallows
widget inline results in production.

Never launch a second poller on the same bot token. `WidgetDispatcher` extends the
existing aiogram poller; it requests `widget_query` in `allowed_updates` and
dispatches that update from the Pydantic `Update.model_extra`, until aiogram
gains native Bot API 10.4 support.

## Transport

- HTML: 9,012 UTF-8 bytes; zlib level 9: 3,596 bytes.
- Enforced budgets: 14,600 bytes (optional network target); Telegram:
  32,768 uncompressed / 4,096 zlib-compressed.
- Widget `chat_data`: ≤1,024 UTF-8 bytes, generated by the server.
- Client requests: `v:<token>:<day-index>` reads one day;
  `s:<token>:<YYYYMMDD>:<start-hex>:<end-hex>:<mask-hex>` saves one day.
  The latter binds the submission to the exact event date and time window,
  preventing a stale widget from writing to an edited schedule.
- Each request must be ≤64 bytes; server responses ≤1,024 bytes.
- Saving uses `save_submitted_availability`, preserving response counts and
  notification semantics. Each day is saved independently, by choice.
- The widget is fixed HTML; data is fetched from the bot as needed. Drafts
  live in message-local `localStorage` until saved, isolated by event, date,
  and event time window.

## Important limitations

- Bot API 10.4 production widgets currently can be sent only in private chats
  and are protected from forwarding. **Group invitations remain text and buttons**.
- The HTML widget is not an internet-hosted page and cannot use external
  JS/CSS/fonts. It has no `fetch`; all writes go through `TelegramWidget.request`.
- Up to 8 hours (32 quarter-hour cells) are shown per page to stay within
  the 600 logical-pixel height limit. At 24 hours, there are three time pages.
- This is a reviewable prototype, not a live-deployed release. Widget runtime
  behavior still needs checking on the current Telegram iOS, Android, desktop,
  and web clients.
- The compatibility dispatcher and method classes should be removed when
  aiogram supports these new Bot API update and method types natively.
- Publishing, merging, tagging, and live bot deployment were not performed.

## Browser preview

Open `src/when2gram/bot/availability_widget.html` locally in a browser.
When `window.TelegramWidget` is absent it displays example event data and
treats Save as a demo-only action.

## Rollback

Set `ENABLE_WIDGETS=false` and restart the single poller. Existing events
and saved availability remain in SQLite. No migration is required.
